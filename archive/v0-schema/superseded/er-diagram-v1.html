Corrections to the mental model

PCN is the match key, but not the join key

The same PCN shows up on resubmissions (frequency 7/8) and on remits from more than one payer. So the match runs once at ingest using PCN plus payer and charge, and the result is stored as remit.claim_id. The agent joins on claim_id, never on PCN directly.

Yes, SVC links to SV1

REF*6R (line item control number) is echoed back on the 835 line when Labcorp sends it. When it's missing, match on procedure code, service date and charge within the already-matched claim. Payers can bundle or split lines, so some remit lines will have no match.

Batches don't link across sides

One EFT pays claims from many 837 files, and payer names rarely match exactly between the two files. To compare by payer, group on payer_name at the claim/remit level instead.

One soft link, not drawn

remit_batch_adjustment.patient_control_number is parsed from the PLB reference when a recoupment names a claim. It's useful for lookups but not reliable enough to be a foreign key.
