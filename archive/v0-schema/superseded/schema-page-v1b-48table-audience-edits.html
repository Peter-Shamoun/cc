A normalized, lossless set of Parquet tables at the true X12 grain: file → transaction → claim → service line → adjustment. Every row traces back to its S3 object and segment span. The agent queries a small set of decoded views; engineers get a byte-exact copy of every segment.

Naming and type conventions

The goal is that a column name alone tells the agent what it holds and how to join it. X12 element references live in comments, never in names.

_idSurrogate key, VARCHAR. Deterministic md5(source_file_id:segment_start), so re-ingesting a file is idempotent.
_numberAn identifier the business or payer assigned (PCN, ICN, trace number).
_codeCoded value, always VARCHAR so "01" and "B7" survive. Decoded in ref tables.
_amountDECIMAL(18,2), stored as sent with its sign. CAS and PLB positive values reduce payment.
_date · _atDATE, and TIMESTAMP in UTC. RD8 ranges split into _start_date / _end_date.
is_ · _countBOOLEAN flags; counts and quantities are DECIMAL(15,3).
one concept, one namepatient_control_number means CLM01 and CLP01 alike, so JOIN … USING works.
prefixesclaim_ 837P · remit_ 835 · ref_ lookups · v_ views · source_ / edi_ / raw_ lineage.
+ lineage blockEvery core row carries source_file_id, transaction_id, source_segment_start, source_segment_end.

Agent-facing tables are what the chatbot queries to answer questions. Engineer-facing tables exist so a developer can trace any row back to the exact file and segment it came from, or inspect rare segments; the agent rarely needs them.

How 837 claims link to 835 remits

CLM01 = CLP01 looks like a clean key but is not unique over time: resubmissions, secondary payers and reversals all share it, and REF*6R only comes back when it was sent. So matching runs once at ingest and writes its method.

Claim level · claim_remit_match
  1. pcn_payer_charge: same PCN, compatible payer, CLP03 = CLM02 (or its negative on a reversal), payment on or after submission.
  2. pcn_payer: the same, without the charge test.
  3. pcn_only: PCN alone, lowest confidence.
  4. payer_claim_control_number: a later replacement or void 837 whose REF*F8 equals the remit's CLP07.
Line level · claim_line_remit_match
  1. line_item_control_number: REF*6R sent on the 837 and returned on the 835.
  2. procedure_date_charge: submitted procedure (SVC06, else SVC01), modifiers, service date and charge, inside an already-matched claim pair.
  3. unmatched_bundled: payer bundled or split the line.

S3 layout and multitenancy

Each customer gets an identical tree under its own prefix, with IAM scoped to that prefix. Tenant isolation lives in the path, not in a WHERE clause.

s3://xifin-cc-<env>/tenants/labcorp/
  landing/837p/YYYY/MM/DD/<original_file_name>     immutable raw EDI (Object Lock)
  landing/835/YYYY/MM/DD/<original_file_name>
  warehouse/v1/
    source_file/ingest_month=2026-10/part-000.parquet
    edi_transaction/ingest_month=2026-10/…
    raw_segment/transaction_type=835/ingest_month=2026-10/…
    claim/submission_month=2026-10/…          every claim_* table uses submission_month
    remit_payment/payment_month=2026-10/…     every remit_* table uses payment_month
    claim_remit_match/  claim_line_remit_match/
    ref/ref_carc/as_of=2026-11-01/ref_carc.parquet
  catalog/cc_v1.duckdb            views + COMMENT ON + data_dictionary for this tenant only
  • Child tables carry the parent's partition column, so one date filter prunes every table in a join.
  • Month partitions keep files large. If a month of a table is under about 100 MB, switch that table to year.
  • Inside a partition, sort by date then patient_control_number; ZSTD; 100K to 1M row groups so DuckDB skips row groups on stats.
  • v1 in the path lets a breaking schema change run alongside the old one.

Key decisions and why

What the agent writes

Six questions and the SQL against this schema. Most need zero or one join.

Open items before DDL

  • Element and qualifier lists come from public TR3-derived references and payer companion guides. Check a few AMT, QTY and REF qualifier names against the licensed TR3 before finalizing.
  • Match rules are a starting heuristic. Calibrate on real Labcorp files, especially PCN reuse across payers and crossover remits (CLP02 19/20, NM1*TT).
  • is_denied only means CLP02 = 4. Business definitions of "denial" belong in views or few-shot examples.
  • Confirm partition granularity against actual Labcorp volumes after the first months load.
