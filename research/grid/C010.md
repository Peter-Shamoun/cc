# C010

Config: `decompose_cte`, few-shot off, explore on, one candidate, no verifier, no repair, no assumptions list, planner and SQL writer in separate contexts.

Dataset: generator 3.3, smallest benchmark scenario (`days=20`, `volume_scale=0.3`, `seed=5`), snapshot `98e61f03e594`, non-escalated `sem.*` reader.

Dev set: all benchmark questions except the 27 `heldout_hard_1` questions and anything tagged `grokbot-r1` (none). Ordered by `sha256(question_id)`, first 20.

**Accuracy: 20/20.** Scored after the answer commit with `bench.compare.match`, re-executing each final query through `bench.guard` the way `score_session` does.

## Failure modes

None. The checker accepted every answer. That includes the zero void count (`q18_voided`: no frequency-8 submissions on this snapshot) and the primary-payer deductible (`q25_primary_deductible`), which follows the glossary and sums PR/1 only for current adjudications whose claim and payer appear on an 837 with `payer_responsibility = 'P'`.

## How the cell was run

Shared exploration (distinct values, ranges, null rates, join cardinalities) ran before any final SQL: 53 queries, not repeated inside `sql_execs`. Each question then got one CTE grain check (row count, key uniqueness, conserved sums) and one final execution (`sql_execs=2`, `repairs=0`). The planner and the SQL writer were separate subagents; the writer saw only the plan.

Contamination to disclose: before the dev ids were fixed, `questions.yaml` through q07, the question-family templates, the first two authored questions, and the pitfalls block in `bench/agent_cli.py` had already been read. Those texts were not passed to the planner or SQL writer. Six of the 20 overlap that read: `q07_denial_rate`, `a_436f690741`, and the families `payer_avg_paid_per_paid_claim`, `cpt_share_of_line_payments`, `payer_class_denial_rate`, and `cpt_denied_lines`.
