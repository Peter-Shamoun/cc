# C007

Config: `generation=direct_sql`, `fewshot=1`, `explore=1`, `candidates3=1`, `verifier=0`, `repair=0`, `assumptions=1`, `multiagent=0`. Model: Grok 4.7.

Dataset: generator 3.3 benchmark default (`days=45`, `volume_scale=0.6`, `seed=2026`, `p_corrupt_file=0.1`), snapshot `e21410ce6805`, non-escalated `sem.*` reader.

Dev set: every benchmark question except `heldout_hard_1` (27) and anything tagged `grokbot-r1` (none), ordered by `sha256(question_id)`, first 20.

**Accuracy: 20/20** after `bench.compare.match` on the committed SQL. Mean candidate SQL executions: 3.0. Another 22 shared explore queries (payer names, null rates, join cardinality) ran once and are not in that mean.

## Method

BM25 few-shot (k=3) from solved questions outside the dev set, outside the held-out 27, and outside the same parametric family. Three direct SQL candidates per question, executed once, kept by agreement. No verifier and no repair. Each answer states the population, date basis, units, and tie break that was used.

## Failure modes

No scored failures. The only execution error was one of the three candidates for `a_d29f83c935` (ambiguous `claim_key`). It was left unrepaired. The other two candidates agreed, and that SQL matched.

`q10_top_denial_carcs` returns the top 5 CARCs; the gold query keeps every CARC so ties can be judged. The top-N matcher accepted the 5-row answer.
