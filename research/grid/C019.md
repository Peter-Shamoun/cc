# C019 — CTE decomposition, critic, assumptions, two agents

Sequential cell, same agent as C002. Same 20 dev questions. Snapshot `e21410ce6805`.

Config: decompose into CTEs, no few-shot and no data exploration, one candidate, a fresh-context critic, repair off, assumptions on, planner and SQL writer in separate contexts.

A planner subagent wrote the population, date basis, units, ties, and CTE checks. A writer subagent saw only that plan and produced the SQL. Each CTE was executed for row count, grain-key uniqueness, and sums. The critic then checked the question text against the SQL and the result and accepted all 20, so the single allowed revision was not used. The chosen revenue-cycle assumption is stored with each answer. Repair stayed at 0.

## Accuracy

**20/20** under `bench.compare.match`. Mean SQL executions: 9.8.

## Failure modes

None. Grain keys that the plan required to be unique were unique. Repeated payer class or procedure values are the grouping dimensions, not duplicate keys.
