# C003 — direct SQL, repair on, no other aids

Config: `generation=direct_sql`, `fewshot=0`, `explore=0`, `candidates3=0`, `verifier=0`, `repair=1`, `assumptions=0`, `multiagent=0`. Model: grok-4.7.

Dataset: frozen generator 3.3 via `bench.dataset.snapshot()` (default scenario: 45 days, volume scale 0.6, seed 2026, `p_corrupt_file=0.1`), dataset id `e21410ce6805`. Queries ran in a non-escalated `open_snapshot` reader over `sem.*`.

Dev set: every benchmark question (handwritten, generated families, authored) except the 27 `heldout_hard_1` questions and anything tagged `grokbot-r1` (none in this tree). Sorted by `sha256(question_id)` and the first 20 were taken. n=20.

Method: one SQL statement per question from the question text, the basic glossary, and the semantic-layer dictionary. No value probes before the final statement. Each first execution returned rows and was kept, so repairs stayed at 0. Mean SQL executions: 1.

Scoring (matcher) is recorded in `C003.json` after the answer commit. Failure modes are appended there.
