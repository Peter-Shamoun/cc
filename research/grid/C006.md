# C006

Config: `decompose_cte`, few-shot off, explore on, one candidate, verifier on, repair off, assumptions on, planner and SQL writer split.

The dev set is the first 20 benchmark question ids by sha256, after removing the 27 `heldout_hard_1` questions. Nothing in the benchmark was tagged `grokbot-r1`. Answers were written against the frozen generator 3.3 snapshot `e21410ce6805` (benchmark default scenario) through a non-escalated `sem.*` session.

A planner produced the grain, population, and CTE checks. The SQL writer probed payer spellings, class tokens, null rates, and join uniqueness, then checked each CTE before the final statement. A fresh-context verifier reviewed population, units, and invariants and accepted all 20 queries, so none were revised. With repair off, no query was rewritten after its final execution.

## Result

Accuracy **20/20** after scoring the committed SQL with `bench.compare.match` on snapshot `e21410ce6805`. No failure modes. The fresh-context verifier also accepted every query, and repair stayed at 0.

## Assumptions that the answers state

- Denial rates and shares are 0-1 fractions rounded to 4 decimals unless the question asks for a percentage.
- Primary payer is `payer_responsibility = 'P'`, using the latest primary submission when the claim needs one class.
- Service-line denial counts use `line_is_denied` on current 835 lines and the billed procedure code.
- Patient responsibility and paid dollars use the current adjudication claim fields, not check totals and not line-level sums, except where the question is about service lines.
